把 **Chrome / Edge / Firefox 里的书签** 同步到你自己的 FavsHub 网站，并在浏览网页时快速收藏、搜索已同步书签。

> 扩展不能单独使用：需要先有一个可访问的 [FavsHub 网站](../favshub-nuxt/README.md)（自托管或你管理的实例），并在扩展里填入该站点地址。

---

## 你能用它做什么

| 功能 | 说明 |
|------|------|
| **书签同步** | 读取浏览器书签树，上传到网站；以网址去重，尽量少打扰已有图标 |
| **双向同步** | 上传：扁平化书签树交网站去重合并；下载：三次 diff（快照 × 服务端 × 浏览器）增量合并，本地新增的书签不会被误删 |
| **一键收藏** | 扩展图标 / 右键菜单收藏当前页（标题、链接、图标） |
| **侧边栏** | 快捷键打开侧栏，随时查看与管理 |
| **浮动球** | 页面内快捷入口（可按需使用） |
| **站内搜索** | 在扩展里搜已同步到站点的书签 |
| **中英界面** | 跟随浏览器语言，也可在设置中切换 |

## 安装

### 前提

1. 已部署并打开 FavsHub 网站（例如 `https://你的域名` 或 `http://localhost:3090`）  
2. 已在网站上 **注册并登录** 过（扩展需要账号令牌）  
3. Chrome / Edge 需 **114 或更高版本**（侧边栏 API 门槛，manifest 已声明 `minimum_chrome_version`）  
4. 本机已安装 [pnpm](https://pnpm.io/) 与 Node.js（从源码构建时）

### 从源码构建并加载（开发 / 自用）

```bash
cd favshub-ext
pnpm install
pnpm build          # Chrome / Edge：产物在 .output/chrome-mv3/
pnpm test           # 单元测试（vitest，覆盖同步 diff 等纯函数）
# 或
pnpm dev            # 开发模式（改代码自动重建）
```

**Chrome / Edge：**

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）  
2. 打开「开发者模式」  
3. 「加载已解压的扩展程序」→ 选择目录  
   `favshub-ext/.output/chrome-mv3/`  
   （`pnpm dev` 时以 WXT 实际输出目录为准）

**Firefox：**

```bash
pnpm build:firefox
# 在 about:debugging 中临时载入生成的扩展
```

发布用 zip：

```bash
pnpm zip
pnpm zip:firefox
```

## 使用指南

### 第一次配置

1. 点击工具栏上的 FavsHub 扩展图标，打开 **设置**  
2. 填写 **网站地址**（与浏览器访问站点时一致，无多余路径，例如 `http://localhost:3090`）  
3. 使用网站账号 **登录**（或按界面提示完成认证）  
4. 打开 **同步**，执行一次完整 / 增量同步  
5. 回到网站首页，应能看到同步后的书签与文件夹  

若同步失败，请检查：网站是否可访问、账号是否正确、站点 CORS / HTTPS 是否与扩展请求匹配。

### 日常操作

| 你想… | 怎么做 |
|--------|--------|
| 把浏览器新增书签同步上去 | 打开扩展 → 同步（或等待已配置的定时同步） |
| 收藏当前正在看的网页 | 点扩展图标的收藏 / 使用右键菜单「收藏到 FavsHub」 |
| 快速找书签 | 扩展内搜索；或在网站首页搜索 |
| 侧边栏管理 | 快捷键打开侧栏（见下表） |
| 换语言 / 主题 | 扩展设置页 |

### 快捷键

| 快捷键 | 功能 |
|--------|------|
| `Alt+B`（Mac 上多为 `Cmd+B`，以浏览器实际绑定为准） | 打开侧边栏 |

可在浏览器的「扩展快捷键」页面中修改。

### 和网站怎么分工

```text
浏览器书签  ──同步──►  FavsHub 网站（长期保存、卡片展示、精选集、多设备访问）
当前网页    ──收藏──►  同上
网站上的管理、精选集、提示词  ──仅在网站完成──
```

- **删改文件夹结构**：以同步策略与网站后台为准；重要数据建议在网站侧确认后再大范围清理浏览器书签。  
- **精选集 / 提示词**：只在网站使用，扩展不负责。

## 同步时会发生什么（通俗说明）

1. 扩展读取浏览器书签树  
2. 整理成「标题 + 网址 + 文件夹路径」发给网站  
3. 网站按 **网址** 判断是否已有：已有则更新标题/分类等  
4. 单独上传 favicon（浏览器缓存的图标转 base64），方便网站卡片展示

**从网站下载到浏览器**（增量合并）：

1. 拉取网站的书签与文件夹  
2. 与「上次同步快照」和当前浏览器书签做 **三方对比**  
3. 服务端新增 → 添加；服务端已删除 → 移除；标题变更 → 更新  
4. 浏览器本地新增的书签不在快照里，**永远不会被同步删除**

首次同步可能较久（书签很多时）；之后增量会快很多。

扩展会申请例如：

| 权限 | 用途 |
|------|------|
| 书签 | 读取 / 配合同步浏览器书签 |

| Favicon | 获取站点图标 |
| 浏览历史 | 网站搜索栏的浏览历史联想（经扩展中继，带速率限制与入参校验） |

## 已知问题

- ~~**文件夹名含 `/` 时的同步 key 歧义**~~：已修复——文件夹名段在拼入 key 前做最小转义（`/`→`%2F`、`%`→`%25`，见 `utils/diff-engine.ts` 的 encodeKeySegment/decodeKeySegment），不含这些字符的名称 key 不变，存量快照天然兼容；名称含 `/` 的文件夹在升级后首个同步周期会跳过快照比对（增删均被安全忽略），第二个周期起恢复正常跟踪。
- **文件夹名含 `/` 的上传侧限制**：上传经网站的 `folder_path`（按 `/` 分层）表达层级，浏览器里名称含 `/` 的文件夹上传后会在网站侧被拆成多层嵌套文件夹（下载侧 key 已转义，不受影响）。属服务端路径模型的固有限制，需网站协议支持才能彻底解决。
