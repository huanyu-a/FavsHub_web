# tokenhub

「论坛福利信息自动化 → 存活检测 → 发布」这个功能的调研、方案与可行性论证归档。

> **当前状态：P0 + P1 已实施并上线（2026-10-09）**。爬虫（`crawler/`）每 3 小时一轮在本机跑，
> 「福利 Key」页已发布：<https://hao.bx9y.com.cn/tokens/keys>。落地方案与实施留痕见 `docs/08`。
> **未实施**：A 类推广 → `token_deals` 发布链路、www 入口按钮、P2 全部可选模块（详见「未完成项」）。

## 这个功能想做什么

自动爬取论坛（<https://linux.sb> 的「福利放送」等板块）里别人分享的大模型 API key 与推广信息：

1. 判断一条帖子是**推广信息**还是 **key 分享**（含「回复后可见」「积分兑换」两类特殊帖的识别）；
2. 推广信息 → 并入「白嫖通告」（<https://hao.bx9y.com.cn/tokens>）；
3. key 分享 → 进一个「福利 key 页面」，并**持续检测 key 是否还活着**，失效的从通告剔除、页面置灰；
4. 每 3 小时刷新一次有效清单（网页 + RSS）。

## 三个最关键的调研发现

1. **「哪些是福利帖」有确定性答案** —— 论坛程序会给「回复后可见」帖自动注入标准占位文案（`回复后可见 回复本主题后即可查看这部分内容。`），聚合 API 原样返回：严格正则实测 6/6 全中、对照组 0 误报。「没写回复领 key 的帖怎么分辨」是个伪难题。
2. **聚合 API 泄漏回复可见内容 + 200 字截断可绕开** —— 第三方聚合 `linuxsb.tux298.com/api/latest` 返回帖子原始文本（含 `[回复可见]` 内部内容，泄漏率约 1/6）；截断靠候选帖回源 `/topic/<tid>` 的 JSON-LD `articleBody` 拿全文解决（实测 1037 字符）。
3. **写入与探测都近乎零成本** —— FavsHub 已有 PAT 鉴权写入通道（推广类零代码改动）；key 存活探测全走 `/v1/models` 只读端点不计费，但各家状态码语义极不统一（xAI/Google 用 400、OpenRouter `/v1/models` 公开、403 永不直接判失效），须照判定表实现。

## 已完成（P0 + P1）

- **P0**：`crawler/` 宿主侧 Python（发现 → 补全文 → 分类 → 提取 → 探测 → 发布）+ SQLite + 静态 feed；
- **P1**：FavsHub 侧 `token_keys` 三表 + `POST /api/ai/token-keys` 上报 + `/tokens/keys` 页面 + `copy` 专用端点 + sitemap/导航；
- **运维**：计划任务 `tokenhub-crawler` 每 3 小时一轮（`scripts/run-round.cmd`：本地爬 → 快照 scp → 服务器侧 push）。
