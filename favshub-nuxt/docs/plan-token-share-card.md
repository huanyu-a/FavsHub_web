# Token 通告分享卡片 — 设计与实现

> 状态：**已上线**（`1fa0705`，后续修复 `14ade80` / `145db58`）| 2026-09-17
> 需求：通告详情支持一键分享，将渠道信息生成 **竖版 3:4 信息卡图片**，右下角附详情页二维码，可点击/长按保存到本地。

## 1. 前置缺口与解法

详情页原本是**纯客户端弹窗**（`components/tokens/TokenDealDetail.vue`），没有可分享 URL。

**解法**：新增 `/tokens?deal=<id>` 查询参数 —— 打开/关闭弹窗与 URL 双向同步，扫码落地自动打开对应弹窗。

- `pages/tokens/index.vue`：`openDetail()` / `closeDetail()` 同步 `route.query.deal`；`onMounted` 检测 `?deal=` 并拉起弹窗（仅传 id，内容由弹窗自行拉取，未过审/不存在时由弹窗提示）。
- 二维码内容即该绝对 URL，容错级别 M、无留白（卡片内自带 5pt 白边）。
- 域名取 `window.location.origin` —— `public.baseUrl` 默认值是 `https://favshub.com`，与线上 `hao.bx9y.com.cn` 不一致，用运行时域名可避免分享链接指向错误站点。

## 3. 卡片版式（900 × 1200 @2x，三风格）

绘制坐标按逻辑尺寸 450 × 600 计算，`ctx.scale(2)` 输出 2 倍图。
三风格由 `BuildShareOptions.style` 切换（`magazine` 默认 / `neon` / `clay`），分享面板顶部有「杂志 / 终端 / 暖阳」分段切换，切换即重新生成；下载文件名非默认风格带后缀（`...-neon.png` / `...-clay.png`）。

## 4. 技术选型

| 方案 | 结论 |
|---|---|
| **A. 前端 Canvas 2D 手写（采用）** | 版式固定、字段有限；零 DOM/跨域依赖；精确控制 2x 高清输出；系统字体栈无 webfont 加载坑 |
| B. DOM→图片（html-to-image 等） | favicon 跨域、字体未加载完成、Safari 兼容三类坑真实存在，分享图翻车成本高 |
| C. 服务端生成（satori/resvg） | 引入部署依赖与缓存问题，分享是纯前端高频轻操作，无必要 |

- 二维码复用已在依赖中的 `qrcode@1.5.4`，**动态 import** 保持独立分包（实测构建后仍为懒加载 chunk）。
- favicon 走同源 `/api/favicon` 代理 → canvas 不被污染，`toBlob` 可直接导出。

### 保存链路（按能力逐级降级）

1. **iOS / iPadOS**：`navigator.canShare({ files })` → `navigator.share({ files })`（「存储图像」即存相册）；
2. **桌面 / 安卓**：`a[download]` + blob URL，文件名 `favshub-token-deal-<id>.png`；
3. **兜底**：toast「请长按图片保存到相册」—— 预览层本身就是 `<img>`，移动端长按保存是原生能力。

## 6. 上线记录与踩坑（2026-09-17）

已上线（`1fa0705` → `145db58`）。上线后抓到两个「Node 侧验证覆盖不了」的真问题：

| 坑 | 现象 | 根因与修法 |
|---|---|---|
| CSP 拦 `blob:` | 预览 `<img>` 破图只剩 alt 文本 | 全站 CSP（`nuxt.config.ts` routeRules `/**`）`img-src` 原本只有 `'self' data: https:`，`URL.createObjectURL()` 生成的 `blob:` 地址被拒载 → 加 `blob:`（`14ade80`）。其余 `createObjectURL` 均为 `<a download>`，不受 img-src 约束 |
| 移动端底栏压弹窗 | 底部导航盖住详情/分享/编辑弹窗的底部按钮，且弹窗打开时底栏仍可点 | 底栏 `z-index: 9998` 高于弹窗（1200/1300），而移动端弹窗是贴底 sheet → 详情 10050 / 编辑 10060 / 分享 10070，保持相对顺序；底部操作区补 `env(safe-area-inset-bottom)`（`145db58`） |

**经验**：涉及浏览器 API + 安全头（CSP）或层叠上下文的功能，Node 侧渲染验证不够，上线前必须真浏览器（含移动端视口）过一遍。CSP 是页面响应头，改完需整页刷新才生效。
