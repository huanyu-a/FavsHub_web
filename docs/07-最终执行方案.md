## 一、一页纸总览

**做什么**：自动爬取 linux.sb（福利放送/我要推广/资源分享板块）→ 分类（推广 / 明文 key / 回复可见 / 积分发卡 / 其他）→ 推广并入 hao 站白嫖通告，key 进新的 `/tokens/keys` 页面 → 每 3 小时验活，死 key 从通告与 feed 剔除、页面置灰标红可筛选不删除 → 网页 + RSS 发布。

**两条链路的价值定位（已定案）**：推广链路是**主力产出**（板块 8 实测 62/100 是推广、规则零误判、写入通道现成）；key 链路是**捡漏**（新样本产量可能长期个位数），价值在「验活 + 聚合 + 登录揭示」，产量问题由 P0 七天闸门用真实数据回答。

**分三阶段，两个决策闸门**：

| 阶段 | 内容 | 动线上站点？ | 闸门 |
|---|---|---|---|
| **P0** | 服务器宿主 Python 爬虫全链路（发现→富集→分类→提取→探测），输出本地 SQLite + feed.xml + 日报 | **否**（零写入、零站点改动） | 跑满 7 天 × 8 轮，用数据回答三个问题（§5.5） |
| **P1** | FavsHub（hao 站）双表 + 读写端点 + **登录揭示端点** + `/tokens/keys` 页面 + 导航/sitemap + www 入口 + feed.xml nginx 直出；爬虫切 PAT 写入 | 是（全是新增，可整体回滚） | P1 验收全绿 + 跑稳两周决定普通 PAT→管理员 PAT |
| **P2** | 可选模块，全部显式开关默认关：养号自动回复、人工补充队列正式化、通知 Bot、LLM 复判 | 是 | 逐个按 P0/P1 数据决定是否开启 |

**唯一高风险项**：P2 养号过 Cloudflare Turnstile——默认关、有完整降级路径，不阻塞 P0/P1。

## 四、最终架构

```
┌───────── 服务器宿主 cron（0 */3 * * *，Python，scripts/tokenhub-crawler/）─────────┐
│                                                                                  │
│  ① 发现   sources/linux_sb.py：GET 聚合API ?forum={2,8,3}（带UA）                  │
│           游标 tid > watermark；兜底 sitemap.xml lastmod；正文前40字符指纹去重        │
│  ② 富集   候选帖逐个 GET linux.sb/topic/{tid}（每轮约6-8个，常规步骤）               │
│           ├─ JSON-LD(@graph).articleBody → 完整首帖全文（绕200字截断）               │
│           ├─ nb-editor-reply-visible-locked → C 类复核                             │
│           └─ .virtual-card-box / 发卡徽标 → D 类（只记录，不提取不探测）              │
│  ③ 分类   B→C→D→A→E 规则引擎；通用规则与来源专属规则分层（D10）；低置信→人工队列      │
│  ④ 提取   分层正则 + (key,base_url) 配对（high/medium/low + 探针消歧）               │
│           B类→存 key（脱敏+hash+密文）；C类→只存原帖链接+领取指引（D2，不碰key）       │
│  ⑤ 探测   /v1/models 判定表 + 状态机；unknown 不判失效；dead 需连续2次一致           │
│  ⑥ 发布   P0：本地 SQLite + feed.xml + 日报（不写任何站点）                          │
│           P1：推广→POST /api/ai/token-deals（先按url查存量去重，D11；普通PAT→pending）│
│               key →POST /api/ai/token-keys（新增端点）→ hao /tokens/keys            │
│               揭示→POST /api/ai/token-keys/[id]/reveal（登录+限频+审计，D2）         │
│               feed.xml 排除死key；页面置灰保留可筛选（D3）                           │

└──────────────────────────────────────────────────────────────────────────────────┘
```

### 5.3 P0 边界（明确不做）

- 不写 FavsHub、不 POST 任何站点、不改任何 nginx/容器/cron 以外的线上配置；
- 不做养号（D1，P2 开关默认关）；不做群通知（D4）；不做 LLM 复判（P2）；
- C 类帖只记录「链接 + 指引」，**不尝试**提取 gated 内容（聚合 API 泄漏的那 1/6 属 B 类正常提取路径，命中即入库，不算养号）。

### 5.4 验收标准（06 修订后）

1. 连续跑 **7 天 × 8 轮**不报错，单轮 <5 分钟；
2. key 探测**误报率 <5%**（判 invalid 的样本人工复查 ≥95% 真失效）；
3. 推广分类在 **50 条人工标注边界样本**上精确率 ≥90%；**23217 型帖 100% 判为 C 类**；
4. **(06 修订，条件式)** 7 天内出现 key 则提取成功率 100%（含 ≥1 把来自 200 字截断之后的全文）；**产量本身（含 0）作为闸门数据记录，不设下限**——产量为 0 不是验收失败，是闸门结论；
5. 人为注入 1 把失效 key，验证「连续 2 次一致才判 dead + feed 排除 + （P1 后）页面置灰可挽回」全链路；
6. 聚合源人为断连一次，验证 sitemap 兜底 + 钉钉告警生效。

### 5.5 七天闸门：数据回答三个问题 → 决定后续投入

| 问题 | 数据来源 | 决定的事 |
|---|---|---|
| key 真实产量与存量规模？ | 日报累计 | 产量可观 → P1 全量做；产量≈0 → **P1 只做推广链路 + C 类指引页**（推广链路独立成立且产出高，这是止损点） |
| 不养号漏掉多少 gated key？ | C 类帖计数 − 泄漏命中数 | 漏损大且用户仍想要 → P2 开 `ENABLE_ACCOUNT_FARM` 评估；漏损小（预期如此：gated 仅 6/100 且 C 类按 D2 只发指引）→ 养号永久不开 |
| 判定表误报率？ | invalid 样本人工复查 | 误报模式回填 02 文档 B.2 判定表（尤其「额度耗尽/限流」两格目前是文档级） |

1. `/tokens/keys` 可访问、可按状态筛选、默认脱敏、顶部有免责声明；

### 8.3 存活探测协议

**探测序（成本优先）**：

| 级 | 动作 | 计费 |
|---|---|---|
| 0 | `GET {origin}/api/status`（New API 系公开）预检站点存活；5xx/`000` → 本轮该主机全标 unknown 并跳过 | 0 |
| 1 | 厂商原生只读端点：OpenRouter `GET /api/v1/key`（其 `/v1/models` 公开 200，**不能用于校验**） | 0 |
| 2 | `GET /v1/models` + `Authorization: Bearer`，**只读状态行 + 前 4 KB，必须丢弃大 body**（成功响应实测可达 751 KB） | 0 |
| 3 | 换鉴权方案重试：`x-api-key`、`x-goog-api-key`、`?key=` | 0 |
| 4 | 仅当 2/3 全 404/405 时降级 `POST /chat/completions max_tokens=1` | **唯一计费步，`ENABLE_PAID_PROBE=false` 默认关** |

**判定表**：

| 判定 | 可观测特征 |
|---|---|
| 无效凭证 | 多数 401；**xAI/Google 为 400**；message 含 invalid/无效/Incorrect/not found |
| 额度耗尽（凭证有效） | **不是 402**：OpenAI 429+`credit_balance_exhausted`；New API 403+`insufficient_user_quota` |
| 限流（凭证有效） | 429，可能带 `Retry-After`；OpenRouter 另有 `X-RateLimit-*` |
| 路径错 | 404；尾斜杠 307（不跟随重定向会误判）；排除后 → `endpoint_unsupported` 不判失效 |
| WAF | 403 + `text/html` + `Just a moment...` → `blocked_by_waf` |
| 中转站管理 API | 200 但 `success:false` → 看 body 字段，状态码不可用 |

**必须读 body 的 5 组同码歧义**：401(无效 vs 未提供→探测构造错误换鉴权重试)；403 五义(额度/IP白名单/分组/地区/CF)；429 二义(限流/耗尽)；404 二义(路径/未实现)；200 二义(成功/管理API鉴权失败)。中转站 `error.type` 由运营者自定义（实测 5 种取值），**依赖字面量必然误判**。

**降误报铁律（全部实测来源）**：
- `000`/超时/5xx → `unknown` 退避重试，**绝不判失效**（最大误报源：60 路并发实测 3.3%~6.7%）；
- **403 永不直接判失效**（先看 Content-Type 与 body 分流 quota/restricted/blocked_by_waf）；
- 401 需 body 佐证：`未提供令牌`=构造错误（换鉴权重试）；`无效的令牌`/`Incorrect API key` → invalid 候选；
- 400（xAI/Google）→ `API_KEY_INVALID` → invalid 候选；其他 → unknown；
- **dead 需连续 2 次一致 invalid**（间隔 ≥30s，必要时换 UA）；401/403 不重试但 60s 后复探 1 次去抖。

**状态机**：

```
                      ┌─────────┐  首次探测
      分享入库 ──────▶ │ unknown │────────────┐
                      └────┬────┘            │
                  探测成功 │                 ▼
        ┌──────────────────┼──────────┐  ┌──────────┐ ◀─ 连续2次一致invalid（间隔≥30s）
        ▼         ▼        ▼          ▼  │   dead   │    dead：feed/通告排除+页面置灰标红
   ┌────────┐ ┌──────────┐ ┌──────────┐  └──────────┘    页面保留可筛选，每天复探1次可挽回
   │ valid  │ │ limited  │ │  quota   │
   └────────┘ └──────────┘ └──────────┘   restricted / blocked_by_waf / endpoint_unsupported
        ▲          │            │         → 待确认/人工复核队列；unknown 连续5轮未决 → 人工队列
        └──── 复探恢复 ─────────┘
```

复探节奏：valid/limited 每 3 小时随 cron；dead 每天 1 次（防误报挽回）。

**并发与成本**：单主机 ≤2、全局 ≤16、同主机间隔 ≥0.5s；429 按 `Retry-After` 否则 `min(60s, 2^n×1s)`+jitter；5xx/`000` → 1s/4s/10s 最多 3 次；单轮 100 条约 25-40s；**token 费用 0**。

### 8.4 数据模型（最终版 SQL，含 06 修订）

```sql
CREATE TABLE IF NOT EXISTS token_keys (
  id TEXT PRIMARY KEY,
  source_id TEXT DEFAULT 'linux_sb',   -- (06 修订) 多源适配：与 source_tid 构成复合来源标识
  source_tid INTEGER,                  -- 来源帖子，可回溯（下架/审计用）
  source_url TEXT DEFAULT '',
  source_title TEXT DEFAULT '',
  source_author TEXT DEFAULT '',
  key_masked TEXT DEFAULT '',          -- 脱敏展示（前6+后4）；C 类指引记录留空
  key_hash TEXT DEFAULT '',            -- sha256，去重用；C 类留空
  key_encrypted TEXT,                  -- 完整 key 加密存储（服务器侧密钥，不进 git），仅供复探与揭示端点；C 类恒为 NULL（D2：不提取不存储）
  base_url TEXT DEFAULT '',
  provider TEXT DEFAULT '',
  models TEXT DEFAULT '[]',
  source TEXT DEFAULT 'post',          -- post | aggregator_leak | reply_visible_guide（C 类指引，06 修订：复用本表少建一张）
  confidence TEXT DEFAULT 'low',       -- 配对置信度 high|medium|low
  verdict TEXT DEFAULT 'unknown',      -- valid|quota|limited|dead|unknown|restricted|blocked_by_waf|endpoint_unsupported
  consecutive_failures INTEGER DEFAULT 0,
  last_probe_at INTEGER,
  first_seen_at INTEGER,
  deal_status TEXT DEFAULT 'published',-- published|hidden（hidden=收到权利人通知即下架，D12）
  note TEXT DEFAULT '',
  created_at INTEGER, updated_at INTEGER,
  UNIQUE(key_hash, base_url)
);
CREATE TABLE IF NOT EXISTS probe_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  credential_id TEXT NOT NULL,
  base_url TEXT NOT NULL,
  probe_kind TEXT NOT NULL,
  http_status INTEGER,
  error_code TEXT DEFAULT '',
  error_message_raw TEXT DEFAULT '',   -- 原始错误信息，仅审计，永不上页面
  attempt_n INTEGER DEFAULT 1,
  verdict TEXT NOT NULL,
  probed_at INTEGER NOT NULL
  -- (06 修订) 保留 90 天：爬虫每轮顺带 DELETE WHERE probed_at < now-90d
);
CREATE TABLE IF NOT EXISTS reveal_log (  -- (06 修订) P1 必做：揭示审计
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  credential_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  ip TEXT DEFAULT '',
  revealed_at INTEGER NOT NULL
);
```

`key_encrypted` 加密密钥放服务器 `.env`（与 PAT 同级保管），不进 git、不进页面、不进日志。

### 8.5 安全与合规红线（贯穿所有阶段）

1. 页面与 feed.xml 默认只展示 `key_masked` + verdict + 置信度；**feed/sitemap 永不包含明文 key**；
2. 完整 key 仅经**登录 + 限频揭示端点**流出，每次揭示写 `reveal_log`（D2）；
3. `error_message_raw` 不渲染到任何前端；
4. `/tokens/keys` 页面顶部免责声明：内容来自第三方论坛公开帖，仅供测试，如有侵权请联系删除（D12）；
5. 「通知即下架」流程：单条 `deal_status='hidden'`（读接口默认过滤 hidden），揭示审计 + `source_id/source_tid` 可回溯来源；
6. C 类帖零接触 key 内容（合规风险最低层，且天然覆盖聚合泄漏拿不到的约 5/6 gated 内容）；
7. 推广写入保留 pending 人工闸门（D9），防自动爬来的 spam 直通 `/tokens`。

| Turnstile 拦截自动回复 | 高（仅 P2） | 默认关 + 连续 3 次失败即停告警 + 人工队列 + 降级路径；不阻塞 P0/P1 |
| 误判失效把活 key 下架 | 中 | 连续 2 次一致 + `000`/`403` 永不判失效 + dead 每日复探 + 页面置灰可筛选可挽回 |
| 推广 spam 混进 `/tokens` | 中 | 普通 PAT → pending 人工闸门 + 正文指纹去重 + url 查存量去重（D11） |
| 聚合源（第三方）停服 | 中 | sitemap lastmod 第一方兜底（分钟级）；不可达自动切换 + 钉钉告警 |
| 富集层回源被加验证/限流 | 低（当前实测零阻力） | 富集失败降级用 200 字文本，只损失截断后凭证，不阻塞当轮 |
| JSON-LD/DOM 结构变更 | 低 | 解析失败即告警降级 |
| FavsHub migrate 失败 | 低 | 独立新表 + 一表一 try/catch + migrate 前手动备份（避开 03:30 窗口）；回滚 = 还原 db + 回退上一 VERSION 镜像 |
| 养号小号被封 | 中（仅 P2 开启后） | 专用小号、≤10 回复/天、行为拟人、封即停 |

**回滚总原则**：P0 = 删脚本目录 + 一条 crontab 行，零残留；P1 全是新增（新表/新路由/新导航项），旧代码不引用新表，回退镜像即回滚；所有写入带 `dry_run` 可预演。任一环节回滚不影响 FavsHub 现网既有功能。
