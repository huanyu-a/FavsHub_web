# 更新日志

本文件记录 `favshub-data-ops` 技能包的版本变更。

版本号规则：**主版本**表示接口有破坏性变更（旧调用会失败）；**次版本**表示新增能力（向后兼容）；**修订号**表示文案修正与勘误。

技能可自查是否有新版本，见 `SKILL.md` 的「技能自身版本与更新」一节。

---

## [1.7.0] - 2026-10-09

- **新增** 复制专用端点 `GET /api/token-keys/{id}/copy`：按需返回 `{ key_plain, base_url }` **完整值**，
  与公开列表同一可见口径（`published`、非 `dead`、回帖指引限 24h；指引行恒 404）。
  公开列表**不再下发 `key_plain`**，且其中 `base_url` 的 key 形态片段（「URL 即 key」的站点）
  已服务端遮蔽 —— 页面渲染、SSR payload、页面源码全程不含完整 key 形态字符串。
- **变更** 公开列表排序改为「B 类优先 → `valid` > `quota` > `limited` > 其他 → 收录时间倒序」，
  可用 Key 排到最前（原排序按探测时间，有效行会被未知行挤下去）。
- **变更** 复制热度计数 `copy_count` 由 copy 端点维护（站点本地数据，爬虫上报不涉及该列）。
- **修正** 技能包版本与站点分发清单此前不同步（`SKILL.md` frontmatter 停在 1.5.0）—— 现已对齐，
  版本号以本文件与 `SKILL.md` frontmatter 为准。

## [1.6.0] - 2026-10-08

- **变更** 「福利 Key」上报协议：上行改传 `key_plain` **明文**（供站点「复制 Key」链路）与
  `post_time`（原帖发帖时间原文字符串）；`key_encrypted` 密文**不再过网**。
- **新增** 对账清理 `POST /api/ai/token-keys/prune`（`delete` scope + 仅管理员，`confirm: true` 必带）：
  每轮快照上报完成后按 `keep` 身份列表清理站点 `published` 存量 —— `dead` / 下架 / 超 24h
  回帖指引行自动从站点消失（`hidden` / `pending` 永不删）。
- **变更** 公开列表 `GET /api/token-keys`：恒定过滤 `dead` 行；回帖指引行仅返回收录 24h 内的
  （与采集端 TTL 双保险）。
- **红线** 明文 key 只在复制瞬间经专用端点下发，绝不进入页面渲染、SSR payload、日志或常规响应。

## [1.5.0] - 2026-10-08

- **新增** 「福利 Key」**上报通道**文档化：采集端经 `POST /api/ai/token-keys`（`write` scope）把探测到的
  Key 快照上报站点，按 `(key_hash, base_url)` **幂等 upsert** —— 普通令牌上报进入 `pending` 待审，
  管理员令牌直接 `published`；支持 `dry_run` 预演。时间戳沿采集端语义存**秒**（与站点其余表的毫秒不同）。
- **新增** 公开脱敏列表 `GET /api/token-keys`（**无需令牌**）：恒定只返回 `published` 行、
  14 字段白名单（`key_masked` 脱敏展示），敏感列（明文 / `key_hash` / `key_encrypted` / 内部诊断）不出现在任何返回。
- **红线** 明文 key、`key_hash`、`key_encrypted` 绝不写入日志、报告或响应正文 —— 向用户汇报上报结果时
  只引用脱敏字段与 upsert 结论。
- 该通道暂无 MCP 工具（REST 专用）；`/api/ai/describe` 的 `endpoints` 清单会同步列出。

## [1.4.1] - 2026-09-29

- **修正** 「第一步永远是 describe」一节补充**返回结构判读纪律**：`endpoints` / `recommended_workflow`
  是**数组**，`rules` / `resources` / `errors` / `caller` / `scopes` / `skill` 是**对象** —— 写检查脚本前
  先判类型（`Array.isArray()` / `isinstance`）再提取；断言必须真的执行、失败即中止，异常被吞等于没检查。
  得出「清单缺少某端点」这类结论前，必须跑一次真实检查并打印命中项 —— 把推断当事实输出会把错误结论
  传导给下游（实例：客户端把 `endpoints` 当 dict 调 `.keys()`，异常被吞后误报「describe 漏登记 edits」，
  实际 29 条端点里 edits 占 5 条、一直都在）。

## [1.4.0] - 2026-09-29

- **新增** 通告**修改建议（提案）通道**文档化：普通用户可对**任何人（含管理员）已公开**的通告
  提交字段级修改建议，经「通告作者」或「管理员」审核后生效 —— `POST /api/ai/token-deals/:id/edits`
  （支持 `dry_run` 预演）、建议列表、「待我审核」列表、`review`（approve/reject）、`withdraw` 撤回。
  MCP 工具同名可用。此前这些端点已在服务端上线但文档从未提及，导致 AI 客户端遇到他人通告
  时只会「删除重建」，丢失原通告的投票与评测记录。
- **变更** 越权编辑已公开通告的响应由 **404 统一返回** 改为 **403 + 提案通道指引**
  （`error` 字段直接给出该通告的 `/edits` 路径）；他人**未过审**通告仍按 404 隔离，不泄露存在性。
- **修正** 技能红线第 4 条与错误码表：明确「不改动他人数据」的合法通道是提交修改建议，不是绕过隔离；
  错误表补注「越权 PUT 已公开通告返回 403 并给出建议通道」。

## [1.3.0] - 2026-09-29

- **新增** 分享卡片 `poster` 风格（夜幕鎏金海报）并成为**默认风格**：额度数字放大至
  ≥10% 图宽、标题 ≥6%，缩略图尺度即可读；`?style=` 省略时出 poster。
- **变更** `style` 参数白名单扩至六种：`poster`（默认）/ `magazine` / `neon` / `clay` /
  `blast` / `voucher`（此前端点只放行 magazine/neon/clay，blast/voucher 会静默回退）。
- **说明** 非法 style 的回退目标由 `magazine` 改为 `poster`。

## [1.2.0] - 2026-09-21

- **新增** 通告分享卡片端点：`GET /api/ai/token-deals/:id/card.png`。
  返回 900×1200 PNG 二进制，三种风格（`magazine` / `neon` / `clay`），
  内容与网页端「分享通告」面板**完全同源**（服务端复用同一份 Canvas 绘制逻辑）。
  此前卡片只能在浏览器里点出来，技能无法产出图片。
- **新增** 响应头 `x-card-style`（生效风格）与 `x-card-cached`（缓存命中状态）。
- **说明** 该端点为 `read` scope；未审核通过的通告仅作者与管理员可取。

## [1.1.0] - 2026-09-21

- **新增** 通告更新端点：`PUT /api/ai/token-deals/:id`（MCP 工具 `update_token_deal`）。
  采用**部分更新**语义 —— 只传要改的字段，未传字段保持原值。
  在此之前更新通告只能「删除后重建」，既不可逆又会丢失投票与评测记录。
- **新增** 技能版本管理：`SKILL.md` frontmatter 增加 `version` 字段，本 `CHANGELOG.md` 记录变更历史。
- **新增** 技能自更新能力：通过站点公开清单 `{BASE}/skills/favshub-data-ops.json`
  一次拿到全部文件的最新正文，无需逐个下载。
- **修正** 通告列表文案：明确 `PUT` 的字段级语义与状态流转规则。
- **强化** 安全红线：新增输出脱敏要求，禁止在回答中出现站点物理部署路径。

## [1.0.0] - 2026-09-17

首个版本，随 FavsHub AI 数据接口一并发布。

- 书签：查询 / 单条或批量新增（≤50）/ 更新 / 删除
- 文件夹：建目录树 / 改名 / 调整层级 / 删除（书签解绑而非删除）
- 提示词：增删改查 / 收藏 / 版本号自增 / 回收站恢复
- 标签：列举 / 新建（同名幂等）/ 删除（仅管理员）
- Token 通告：查询 / 发布 / 删除
- 通用：`dry_run` 预演、删除需 `confirm`、越权一律 404、限频 600 次/分钟
